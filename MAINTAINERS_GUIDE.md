# Maintainer's guide

You don't need to understand the entire application to make small edits. This is a framework-free website: HTML defines the elements, CSS styles them, and JavaScript connects the forms to Supabase.

## File map

| File | What to edit |
|---|---|
| `website/index.html` | Form field labels, option lists, organizer navigation, help text, page sections |
| `website/styles.css` | Colors, fonts, layout, spacing, mobile rules |
| `website/app.js` | Event listings, registration, form behavior, rendering, dashboard actions |
| `website/favicon.svg`, image assets | Browser tab icon and hero background |
| `sql/*.sql` | Privileged backend validation; apply in Supabase SQL Editor, never embed it in the browser |

## Easiest changes

### Change the site's colors

At the beginning of `website/styles.css`, update the CSS variables under `:root`:

```css
:root {
  --navy: #072b44;
  --teal: #008b95;
  --cyan: #19d4e3;
  --body: #f3f8fa;
}
```

### Change homepage wording

In `website/index.html`, search for the exact text in the browser (for example, `Casual games. Good people.`). Edit only the words, not the surrounding HTML tags or `id` attributes.

### Change scheduling defaults

- In `website/index.html`, search for `id="event-hour"` (currently defaults to `18`, or 6:00 PM).
- Search for `id="event-minute"` for the quarter-hour options.
- Search for `id="event-duration"` (currently defaults to `180`, or three hours).
- The date deliberately starts blank.
- The function `clearEditor()` in `website/app.js` resets these defaults. If you change the defaults, update **both** places.

### Change event defaults

Edit `index.html` and `clearEditor()` in `app.js`:

- Venue: `Hillside Community Center`
- Price: `5` dollars
- Capacity: `24` players (a starting value; each event can override it)

### Change email and payment messages

- The on-screen post-registration notice is in `app.js`, in the `signup-form` submit handler near the `emailGuidance` constant.
- The payment option list is in `index.html` under `id="payment-method"`.
- The **actual email contents** are generated by the server-side Supabase email bridge and Google Apps Script, not by these website files. Update and test those separately if wording changes.

## How app.js is organized

Search for these function names to jump to a feature:

| Function | Purpose |
|---|---|
| `loadEvents()` | Load public events and organizer-only private upcoming events |
| `eventCard()` | Render each Upcoming Events card |
| `eventDetailPage()` | Render the full event details and signup panel |
| `loadEventRoster()` | Load public-safe player names and waitlist labels |
| `loadInvitedEvent()` | Load a private event with its invitation token |
| `openSignup()` | Open the player registration form |
| `emailProblem()`, `updateEmailHint()` | Client-side email format / typo checks |
| `loadManageRegistration()` | Keep `?manage=` links from emails working for self-cancellation |
| `refreshAdmin()` | Check organizer status and show organizer-only features |
| `clearEditor()`, `editEvent()` | Set up the Create/Edit event popup |
| `loadAdminEvents()` | Render sorted organizer events, registrations, and actions |

## Safe coding practices

- Change one feature at a time and test locally before updating GitHub.
- Back up known-good files or use GitHub commits to roll back.
- Do not rename `id` values in HTML without updating the matching JavaScript lookups (`$("id")`).
- Use `esc()` when putting player-entered text into an HTML string: this prevents HTML injection.
- Do not paste secrets into frontend JavaScript. **Publishable key** is okay; secret and service-role keys are not.
- Private invite and management links are access credentials. Do not include them in the public event roster, logs, or external analytics.
- Avoid changing the registration or notification SQL RPCs unless you understand their access checks and locking behavior.

## Readability and formatting

JavaScript and CSS use multi-line blocks and two-space indentation. Some HTML templates in `eventCard()`, `eventDetailPage()`, and `loadAdminEvents()` remain inside JavaScript template literals because they are rendered dynamically. These template literals contain HTML; you may edit labels and classes there without rewriting the functions.

If you want to keep formatting consistent going forward, VS Code supports **Format Document**. You can install a standard formatting extension such as Prettier yourself, then choose a consistent style; preview and test any formatter changes before deploying.
